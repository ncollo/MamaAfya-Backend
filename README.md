# MamaAfya Backend: Triage Engine & API Gateways

An asynchronous FastAPI backend for the MamaAfya maternal health platform. This service handles multi-channel symptom ingestion (Progressive Web App & USSD), evaluates clinical risk using a centralized triage engine, and orchestrates emergency SMS dispatch via Africa's Talking.

## 🏗️ Architecture Overview

The system is decoupled to separate the clinical algorithm from the ingestion layer and external services.

*   **`/app/api` (Ingestion Layer):** Contains modular routers for the PWA JSON payloads and the Africa's Talking USSD form-data webhooks. Features a state-driven dictionary router that dynamically serves antenatal or postnatal menus based on the patient's medical phase.
*   **`/app/core` (Triage Engine):** The "brain" of the system. Evaluates reported symptoms and gestational context to return a standardized risk tier (`High Risk`, `Medium Risk`, `Routine`).
*   **`/app/services` (Integration Layer):** 
    *   `sms_service.py`: Uses `httpx` for non-blocking, async HTTP calls to the Africa's Talking SMS API (bypassing older SDK SSL issues).
    *   `event_dispatcher.py`: The bridge module designed to hand off data to the PostgreSQL database and WebSocket server.

## ⚙️ Prerequisites

*   Python 3.9+ 
*   An active [Africa's Talking](https://africastalking.com/) developer account (Sandbox for testing).
*   [Ngrok](https://ngrok.com/) installed for exposing the local server to the USSD gateway.

## 🚀 Local Setup & Installation

**1. Clone the repository and navigate to the directory:**
```bash
git clone <repository-url>
cd MamaAfya_backend

**2. Create and activate a Python virtual environment:**
,
# Windows:
python -m venv venv
venv\Scripts\activate

# Mac/Linux:
python3 -m venv venv
source venv/bin/activate

**3. Install dependencies:**
pip install -r requirements.txt

**4. Configure Environment Variables:**
Create a file named exactly .env in the root directory. Do not commit this file to version control. Add your Africa's Talking Sandbox credentials:
AT_USERNAME=sandbox
AT_API_KEY=your_sandbox_api_key_here


**5. Running the Server & Establishing the Tunnel:**
To test the full omni-channel system, you must run both the FastAPI server and the Ngrok tunnel simultaneously in separate terminal windows.

Terminal 1: Start the FastAPI Application
Ensure your virtual environment is active, then run:
uvicorn app.main:app --reload

The server will start on http://127.0.0.1:8000.

Terminal 2: Start the Ngrok Tunnel
Expose port 8000 to the internet:
Run this in the terminal: ngrok http 8000

Copy the https://... Forwarding URL generated by Ngrok


**6.  Africa's Talking Configuration:**
To route USSD dials to your local machine:

Log into the Africa's Talking Sandbox Dashboard.

Navigate to USSD -> Service Codes.

Create or Edit a service code channel (e.g., 50963).

Set the Callback URL to your Ngrok URL appended with the specific FastAPI route:
https://<your-ngrok-url>.ngrok-free.app/api/ussd/callback

Click Save.


**7. Testing Procedures:**
1. PWA Ingestion (JSON)
Navigate to the interactive Swagger UI: http://127.0.0.1:8000/docs

Open the POST /api/pwa/submit-symptoms route.

Click Try it out and submit the following JSON payload:

JSON
{
  "mother_id": "MOM-98765",
  "gestational_week": 34,
  "symptoms": ["severe_headache"]
}
Verify the server returns a 200 OK with the DISPATCH_CHW action.

2. USSD Gateway (Dynamic Menus)
Open the Africa's Talking Simulator in your browser.

Dial your registered USSD code (e.g., *384*50963#).

You will see the dynamic menu. Selecting a High-Risk symptom will trigger the sms_service.py dispatch logic.

Note on Phase Testing: To test the Postpartum menu, temporarily modify the fetch_patient_context() return dictionary in app/services/event_dispatcher.py to output "phase": "postnatal".

**8. Integration & Handoff Guide:**
To the integrating database/frontend developer:
The core triage logic and API routing are fully stable. To link this domain to the PostgreSQL database and real-time frontend:

Database Link: Open app/services/event_dispatcher.py. Locate fetch_patient_context(). Remove the simulated dictionary and inject your async SQLAlchemy/asyncpg query to fetch the patient's actual phase, gestational_week, and assigned_chw_phone.

WebSocket Link: In the same file, locate notify_chw_dashboard(). Inject your Socket.io emit logic here to push real-time alerts to the frontend dashboard without blocking the HTTP response.

Production Deployment: When moving to a live server, update AT_SMS_URL in app/services/sms_service.py to https://api.africastalking.com/version1/messaging and update the .env file with live billing credentials.
